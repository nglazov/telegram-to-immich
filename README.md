# Фото из чатов

Веб-приложение для проверки и скачивания фото и видео из Telegram. Работает самостоятельно с локальной папкой; отправка в Immich необязательна. Распознавание лиц и отбор по людям остаются в Immich.

По умолчанию выбран **dry run**, расписание выключено. Ключи и авторизация задаются отдельно для каждой установки.

## Локальная проверка

1. Скопируйте `.env.example` в `.env` в каталоге приложения, задайте права `0600` и заполните `APP_PASSWORD` уникальным паролем длиной не менее 12 символов.
2. Получите собственные `api_id` и `api_hash` в [Telegram API development tools](https://my.telegram.org/apps). Заполните `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`.
3. В приложении перейдите в «Подключения» и нажмите **«Перечитать .env»**. Ключи не вводятся в веб-форме, не возвращаются в API и не сохраняются в SQLite.
4. Войдите по номеру, коду Telegram и при необходимости паролю 2FA. Код и пароль 2FA не сохраняются. Telethon сохраняет авторизованную сессию в закрытом локальном каталоге `state/`.
5. На вкладке «Загрузка» обновите список чатов, выберите чаты и даты, сохраните выбор. В супергруппах с темами раскройте **«Темы»**: можно оставить все темы (включая будущие) или снять «Все темы, включая новые» и отметить отдельные темы. Период задаётся для группы и применяется ко всем выбранным темам. Поиск ищет и по названиям тем.
6. Оставьте режим **«Dry run — проверить без скачивания»** и запустите проверку. Отчёт покажет новые и уже скачанные вложения по типам и оценку объёма. Файлы и миниатюры не скачиваются; история импорта и курсоры не меняются; запросов в Immich нет.
7. Когда будете готовы скачивать, явно выберите **«Скачать только в локальную папку»** и нажмите кнопку запуска. Скачанные фото и видео можно открыть из списка последних файлов или из папки `photos/`.

Dry run считает вложения по типам: фото, видео, GIF/анимации и видеокружки. Отдельно показывает галереи и причины пропуска остальных сообщений. Каждый элемент галереи учитывается отдельно; Live Photo содержит два файла. Совпадающее содержимое определяется по хешу после скачивания. Размер берётся из доступных метаданных Telegram, неизвестные размеры отмечаются отдельно. При остановке или ошибке отчёт помечается как частичный. Проверка не отмечает сообщения прочитанными и ничего не отправляет в чаты.

## Режимы запуска

| Режим | Telegram | Локальные файлы | Immich |
| --- | --- | --- | --- |
| Dry run | Чтение истории и метаданных | Не создаются | Не используется |
| Скачать локально | Чтение и скачивание | Сохраняются в `photos/` | Не используется |
| Скачать и отправить в Immich | Чтение и скачивание | Сохраняются в `photos/` | Загрузка в альбомы чатов |

`DRY_RUN=true` выбирает безопасный начальный режим при открытии страницы. Само открытие приложения, изменение настроек, вход или сохранение чатов ничего не скачивают. Реальное скачивание требует явного выбора режима и запуска. Расписание включается отдельно и имеет собственный явно выбранный режим; начальный режим расписания также dry run. Перечитывание `.env` выключает расписание.

При запросе `POST /api/sync` с телом `{}` сервер также выбирает dry run. Отправка в Immich возможна только с `{"mode":"import"}`; локальное скачивание — с `{"mode":"download"}`. Старое расписание версии 0.1 без явно сохранённого режима отключается при обновлении.

## Переменные окружения

Скопируйте `.env.example` в `.env` для новой установки и задайте права `0600`. `.env` исключён из Git и Docker build context. Переменные процесса имеют приоритет над файлом; значения `.env` читаются буквально, без подстановки других переменных.

| Переменная | Назначение |
| --- | --- |
| `APP_PASSWORD` | Пароль веб-приложения, минимум 12 символов |
| `APP_ORIGIN` | Адрес интерфейса, локально `http://localhost:8213` |
| `TELEGRAM_API_ID` | ID собственного приложения Telegram |
| `TELEGRAM_API_HASH` | Hash собственного приложения Telegram |
| `TELEGRAM_DOWNLOAD_DELAY_SECONDS` | Пауза между скачиваниями: 3 секунды по умолчанию, диапазон 0–300; не сокращает FloodWait |
| `IMMICH_URL` | Необязательный адрес сервера Immich, с `/api` или без |
| `IMMICH_PUBLIC_URL` | Необязательный адрес для ссылок в браузере, если `IMMICH_URL` доступен только внутри Docker |
| `IMMICH_API_KEY` | Необязательный ключ аккаунта назначения Immich |
| `DRY_RUN` | Начальный режим: `true` (по умолчанию) или `false` для локального скачивания |

Для изменения Telegram/Immich ключей и `DRY_RUN` достаточно кнопки «Перечитать .env». Изменение `APP_PASSWORD` или `APP_ORIGIN` требует перезапуска. В Docker, где настройки передаются через environment, необходимо пересоздать контейнер после изменения Compose `.env`.

Если в старой базе 0.1 сохранились ключи, при запуске они сначала переносятся в закрытый `.env` (не заменяя уже заданные значения), затем удаляются из SQLite с очисткой WAL и свободных страниц. Если перенос не удаётся, запуск останавливается без удаления исходных значений. Старые резервные копии базы могут содержать прежние ключи.

## Запуск и остановка

Отложенные вручную вложения хранятся в отдельной очереди SQLite и видны в журнале с причиной, датой и числом повторных попыток. Основной проход пропускает их даже после перезапуска или повторного обхода дат; календарь не считает такой день полностью выгруженным. На вкладке журнала можно остановить основной импорт и отдельно повторить скачивание выбранного вложения локально или с отправкой в Immich. Повтор получает свежие сведения о сообщении, соблюдает FloodWait, не меняет курсор основной очереди и при ошибке оставляет запись для следующей попытки. Успешное скачивание атомарно переносит запись в обычную историю. Незавершённые временные файлы удаляются, уже сохранённые оригиналы остаются.

Требуются Python 3.12+ и `uv`:

```bash
git clone https://github.com/nglazov/telegram-to-immich.git
cd telegram-to-immich
cp .env.example .env
chmod 600 .env
# Заполните APP_PASSWORD в .env, затем запустите:
uv sync --frozen
uv run --frozen python -m telegram_photos
```

Открыть [http://localhost:8213](http://localhost:8213). Приложение само читает `.env`; выполнять `source .env` не нужно. При запуске из терминала остановка — Ctrl+C. Один процесс Uvicorn и одна реплика обязательны для SQLite и сессии Telegram.

Для нестандартного запуска: `uvicorn telegram_photos.app:app --host 127.0.0.1 --port 8213 --workers 1 --no-access-log`. Переменные процесса `STATE_DIR` и `PHOTOS_DIR` задают другие каталоги состояния и фотографий; по умолчанию это `state/` и `photos/` относительно рабочего каталога.

## Подключение Immich позже

Оставьте `IMMICH_URL` и `IMMICH_API_KEY` пустыми для полностью локальной работы. Чтобы отправлять фотографии, создайте API-ключ **в том аккаунте Immich, куда должны попадать фотографии из чатов**. Нужны права `user.read`, `asset.upload`, `album.read`, `album.create`, `albumAsset.create`.

Заполните обе переменные, перечитайте `.env`, нажмите «Проверить подключение». Для передачи файлов выберите режим «Скачать и отправить в Immich» и запустите его отдельно. Уже скачанные локально фотографии попадут в очередь отправки без повторного скачивания из Telegram.

Перед импортом проверяется аккаунт назначения, в том числе после изменения ключа в `.env`. После первой успешной загрузки нельзя переключить эту историю импорта на другой аккаунт или сервер: для этого нужна отдельная установка. Замена ключа того же аккаунта допустима. API-клиент написан по OpenAPI Immich v3.2.4; живую версию сервера нужно проверить перед установкой.

Альбомы именуются `Telegram · Название [ID чата]`. Распознавание, отбор и удаление выполняются в Immich. Приложение не запрашивает людей и не удаляет снимки. Если после импорта вы удалите фото в Immich, очередная синхронизация его не загрузит заново.

## Хранение и ограничения

```text
.env                         ключи и пароль приложения, права 0600
state/photos.sqlite3         чаты, курсоры, история импорта, отчёт dry run
state/telegram.session       авторизованная сессия Telegram
photos/.partial/             незавершённые скачивания
photos/inbox/ab/<sha256>.jpg  полные скачанные файлы
```

**Локальные копии сохраняются после отправки в Immich.** Очистка в Immich их не удаляет. Папка скачивания не является внутренним хранилищем Immich. Для резервирования SQLite и Telegram-сессии сначала остановите приложение. Базу и сессию храните на локальном диске, не на NFS; `photos/` можно разместить на NAS. История импорта нужна, чтобы не возвращать ранее удалённые в Immich снимки.

Вкладка **«Журнал файлов»** показывает все уникальные скачанные файлы постранично: размер, время скачивания и отправки, сообщения-источники и состояние импорта. Доступны поиск по чату, номеру сообщения или имени файла и фильтры: ожидает отправки, в Immich и альбоме, в Immich без альбома, ошибка. Совпадающие файлы из разных сообщений объединяются в одну запись с сохранением источников. Счётчики и объём относятся к уникальным файлам, число вложений включает повторения.

У файлов, скачанных до появления журнала, размер восстанавливается с диска, а неизвестные даты обработки остаются пустыми. Дата сообщения не выдаётся за дату скачивания. Изменение периода сбрасывает курсор просмотра, но сохраняет историю: уже известные сообщения повторно не скачиваются, а успешно загруженные в Immich файлы не отправляются снова.

Поддерживаются группы, каналы и темы супергрупп:

| Вложение | Обработка |
| --- | --- |
| Обычные фото и видео | Сохраняется основной файл в доступном оригинальном размере; обложки, миниатюры и альтернативные версии видео не дублируются |
| Фото и видео, отправленные файлами | Тип определяется по MIME и расширению из имени; поддерживается `application/octet-stream`, регистр расширения не важен |
| Галереи, включая смешанные фото/видео | Каждый элемент сохраняется отдельно, общий идентификатор галереи хранится в истории; границы страниц истории не теряют элементы |
| GIF, анимации MP4, видеокружки | Сохраняются исходные файлы, в отчёте отдельные категории |
| Live Photo | Сохраняются фото и короткий видеоклип; в Immich отправляются отдельными файлами, автоматическое объединение в Live Photo не реализовано |
| Пересланные вложения, спойлеры | Обрабатываются как обычные вложения, если доступно сохранение |
| Аудио, голосовые, стикеры и эмодзи | Пропускаются с причиной в dry run |
| PDF, офисные документы, архивы и неизвестные форматы | Пропускаются с причиной; архивы не распаковываются |
| Превью ссылок, истории, платные вложения, опросы, контакты и геопозиции | Пропускаются с указанием категории; внешние ссылки не обходятся |
| Исчезающие, недоступные или защищённые вложения | Пропускаются с причиной; видео, которое Telegram ещё обрабатывает, останавливает скачивание до повторного запуска |

Основные форматы: JPEG, PNG, WebP, HEIC/HEIF, AVIF, TIFF, GIF, BMP, JPEG 2000/XL, PSD и распространённые RAW; MP4, MOV, MKV, WebM, AVI, M4V, MPEG, TS/MTS, 3GP, FLV, WMV и MXF. Точный список расширений и MIME находится в `telegram_photos/media.py`. SVG не импортируется. Сервер Immich должен поддерживать соответствующий формат: [форматы Immich](https://docs.immich.app/features/supported-formats/).

Личные и секретные чаты не включены в выбор. Изменение вложений уже обработанных сообщений не отслеживается. При переходе с версии, которая скачивала только фото, курсоры однократно сбрасываются и расписание отключается. Следующий ручной запуск повторно проверит выбранный период, найдёт ранее пропущенные видео и сохранит историю уже импортированных файлов. При ошибке или остановке между частями Live Photo курсор не продвигается; уже сохранённая часть повторно не скачивается.

Темы супергрупп загружаются постранично, включая «Общее» и закрытые темы. Dry run и скачивание фильтруют сообщения по выбранным темам, включая ответы внутри них. Для фильтрации просматриваются метаданные истории всей группы; файлы из остальных тем не скачиваются. При изменении набора тем курсор группы сбрасывается: история проверяется заново за выбранный период, уже скачанные сообщения повторно не загружаются. Альбом в Immich остаётся общим для группы. При ошибке обновления тем сохраняются предыдущие темы и выбор; ошибка показывается в раскрытом списке.

Обе границы периода включены, часовой пояс — Москва. Пустая конечная дата включает будущие сообщения. Реальное скачивание идёт последовательно. В режиме импорта сначала отправляется накопленная очередь, затем каждый новый файл сразу после полного скачивания передаётся в Immich и добавляется в альбом. Только после этого начинается следующий файл. Ожидания партии или таймера нет; частично скачанный файл не отправляется. В конце страницы истории и всего обхода повторяются оставшиеся неудачные отправки. Остановки и сетевые ошибки не сдвигают курсор за нескачанный файл. Паузы Telegram (FloodWait и FloodPremiumWait) не завершают активную задачу. Повторяется тот же RPC и тот же блок файла, без повторного открытия частичного файла. Время ожидания не меньше ответа Telegram; повторные ограничения без прогресса увеличивают паузу: 30, 60, 120, 240, 480, затем 900 секунд. Получение новых байтов или обработка сообщения сбрасывает серию. Срок паузы и её причина сохраняются в SQLite. Остановка прерывает ожидание; новый запуск соблюдает сохранённый срок. После перезапуска контейнера при выключенном расписании импорт запускается вручную.

`TELEGRAM_TAKEOUT=true` (по умолчанию) включает официальный Takeout для запросов блоков медиа, в том числе на другом дата-центре Telegram. История и выбор тем продолжают читаться обычным API с тем же курсором. Разрешения Takeout соответствуют типам выбранных чатов; контакты не запрашиваются. Незавершённая сессия экспорта сохраняется, после успешного прохода закрывается. Telegram может потребовать отложить начало экспорта (`TakeoutInitDelayError`): этот срок хранится отдельно и не блокирует обычный Telegram API. До разрешения экспорта файлы скачиваются обычным способом; Takeout повторяется между файлами после окончания его паузы. Серверная ошибка Takeout при скачивании блока (RpcCallFailError/ServerError после внутренних повторов Telethon) переключает текущий запуск на обычный API с того же блока; FloodWait никогда не вызывает такое переключение. Подтверждённая сессия экспорта сохраняется для следующего запуска. Takeout не гарантирует отсутствие лимитов. Dry run не открывает Takeout и не скачивает файлы. [Документация Telegram](https://core.telegram.org/api/takeout).

Общий блок статуса доступен на всех вкладках: причина паузы, обратный отсчёт, время следующей попытки, текущий день/сообщение и байты файла. Карта дней показывает количество сохранённых вложений чата, отправленных в Immich и добавленных в альбом. Счётчики относятся к источникам сообщений, поэтому могут превышать число уникальных файлов. Полнота дня подтверждается только после прохода истории выбранных тем за весь день; текущий день не объявляется завершённым. Для старых записей до внедрения карты полнота неизвестна. Смена дат или тем сбрасывает отметки проверки, сохраняя журнал и файлы.

Для фото без EXIF дата сообщения передаётся в Immich как дата создания; оригиналы сохраняют свои метаданные. Сжатые фотографии Telegram скачиваются в наибольшем доступном размере.

## Запуск через Docker Compose

[Compose-конфигурация](compose.yaml) находится в корне репозитория. Значения ключей передаются контейнеру через environment из локального `.env`. Это отдельный Compose-проект; изменение или перезапуск Immich не нужны.

Клонируйте репозиторий и создайте закрытый `.env` из примера, как описано выше. Создайте каталоги `state/` и `photos/` и выдайте права записи пользователю контейнера: по умолчанию UID/GID `1028:1028`. На Linux можно задать `APP_UID` и `APP_GID` равными UID/GID владельца каталогов. Для других путей задайте `STATE_PATH` и `PHOTOS_PATH` в `.env`. `state/` должен находиться на локальном диске; `photos/` можно разместить на NAS.

Выполните `docker compose config --quiet`, затем `docker compose up -d --build`. Не запускайте контейнер и локальное Python-приложение одновременно с одной базой и Telegram-сессией. Порт по умолчанию доступен только на loopback. Для доступа к удалённому серверу:

```bash
ssh -N -L 8213:127.0.0.1:8213 user@your-server
```

Открыть `http://localhost:8213`. Для постоянного удалённого доступа использовать HTTPS reverse proxy с соответствующим `APP_ORIGIN`.

## Проверки

Набор из **92 тестов** проверяет темы, миграции, файлы с общим MIME, GIF, кружки, пересылки, спойлеры, пропуски, смешанные галереи на границе страниц, ошибки и остановки между частями Live Photo, загрузку видео в Immich с повтором альбома, HTTP Range, журнал файлов с фильтрами и пагинацией, расширение периода без повторного скачивания, сохранение старой истории, немедленную отправку каждого завершённого файла до скачивания следующего, отправку старой очереди до обращения к Telegram только в режиме импорта, остановку во время немедленной отправки, повторные FloodWait, остановку во время паузы и продолжение запроса Telegram после короткого ожидания. Скачивание и отправка в Immich тестируются на изолированных данных с подменёнными клиентами; совместимость с конкретным сервером Immich следует проверить отдельно.

```bash
uv run --frozen python -m pytest -q
uv run --frozen ruff check telegram_photos tests
node --check telegram_photos/static/app.js
```

После сборки образа отдельно проверяйте открытие страницы, JavaScript и CSS от пользователя контейнера. Проверка использует временное состояние и не подключается к Telegram или Immich:

```bash
docker run --rm -i --network none --read-only --tmpfs /tmp local/telegram-to-immich:0.2.0 python - < tests/smoke_image.py
```

`uv.lock` закрепляет версии; `requirements.txt` содержит зависимости с хешами для Docker. После изменения зависимостей обновлять вместе:

```bash
uv lock
uv export --frozen --no-dev --no-editable --format requirements-txt --output-file requirements.txt
```
